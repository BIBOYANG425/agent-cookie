# Agent Cookie · 3–5 分钟视频分镜

目标 **4 分 10 秒**，沿用 [plan 第 3 节](plan.md#3--demo-是什么样子的) 的 iMessage 主线：现场一句真实购物需求 → 卡上相关尺码与偏好补全 → 两家真实报价 → 选一家 → 付款交接 → 查授权与撤销 → 回头客 → ACME / coding agent → 架构。按 2026-10-17 人的最新方向，商品、商家、尺码值和预算都不预定；本稿覆盖 plan 第 3 节的旧固定示例，plan.md 仍由人修改。这是录制脚本，不是已发生的结果；镜头是否可用以[证据索引](evidence/README.md)为准。A10/A17 由 B 供片，A15/A16 由 C 供片。

左侧手机 iMessage，右上控制台，右下工作台日志；需读日志时单独放大。全片保留模式角标：**Live** 仅用于当次真实请求；**Fixture replay · captured <UTC 时间>** 用于实录重放；**Sample** 标身份、地址与 ACME 商品。插入已有执行片段时全程显示 **Recorded run · <录制日期>**，并保留当时的数据模式。

## 失败、阻塞与短版

先从 reset 连跑两遍，记录每步真实耗时再剪辑。请求超过 20 秒或出错时，只能切到已有且核验过的 **Recorded run** 并展示当时日志；没有成功原片就保留失败或删段，不合成预期消息。

若 A15/A16 未完成，删除 2:30–3:30 的成功演示，保留一句“第三方 memory 接入仍待 note 生命周期契约补齐”，全片约 **3 分 10 秒**。C11 的 P1 BLOCKED 不阻塞短版稿。若 Claude Desktop 回头客段也无可核验原片，以 25 秒控制台授权解释替换，保持至少 3 分钟。没有 A17 实际 iMessage 原片时，不能标记正式视频已完成。

## 三条备选需求与 Recorded run 切换

现场需求优先，以下仅是现场无想法或网络失败时可选的三个入口；每条预算都属于该次输入，不是产品常量。尺码/语气/篇幅从录制当时卡读取，不能先把卡改成某商品有库存的码数。三条均为现有 shoe 类可讨论的备选，并不代表仅支持这三类，也不宣称任意品类的契约已经完成。

| 备选 | 原话 | 对应材料与可用状态 |
| --- | --- | --- |
| 日常通勤 | “最近每天走路通勤，帮我找双舒服的日常走路鞋，95 美元以内。” | [walking 实录目录查询](evidence/recorded-needs/README.md#三条素材)；完整 iMessage Recorded run 待 B |
| 周末徒步 | “周末想走山路，帮我找双防水徒步鞋，预算 160 美元。” | [hiking 实录目录查询](evidence/recorded-needs/README.md#三条素材)；完整 iMessage Recorded run 待 B |
| 开始跑步 | “想开始在公路上跑步，帮我找双公路跑鞋，140 美元以内。” | [running 实录目录查询](evidence/recorded-needs/README.md#三条素材)；完整 iMessage Recorded run 待 B |

每条正式兜底必须独立录完：原话 → SDK 读卡 → 真实搜索 → 两家报价（或真实不足/尺码限制说明）→ 选择 → handoff/失败 → 地址回执核对（若发生放行，仅选定一家 checkout；未放行也保留事实）。录制时间、代码 SHA、数据模式、卡字段来源及原始响应一起封存。现场失败后先展示失败，再明确切到对应需求的 **Recorded run · UTC 时间**，保留原输入和原预算；现场需求若不同，说明这是另一个示例，不能拿旧报价冒充新请求结果。

当前三条仅有 catalog 支撑素材的记录入口，**未宣称三条完整录像可用**。SDK/Photon 通用意图、非鞋类策略和尺码不符说明待 A/B/D 协作；详见 [requests](requests.md)。旧固定需求 A17 日志只证明其自身历史流程，不替代这三条原片。此状态不是让现场脚本永久固定，接口补齐后重新按性质核验并更新索引。

五分钟上限内可将 A16 两次运行各扩展到 40 秒；不能用时长隐藏失败或把部分接入说完整。
