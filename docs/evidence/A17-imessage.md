# A17 iMessage 主流程（手动） · P0

状态：旧需求的真实收发/选择/handoff 日志已由 B 提供，见[总索引](README.md)；连续原片仍待采集。新方向与三条备选的完整录屏尚未执行，本文是新的取证模板。

通过标准：现场真实需求到两家真实报价（最多两家，不足时解释）再到付款交接或真实失败；不固定店名、价格、尺码。用户已存的相关尺码/偏好由卡补全，报价不超本次预算，地址只给 accept 的那一家。录屏保存到本目录。

## 执行前

- 记录日期、执行人、仓库提交、Photon 配置版本、工作台版本、UCP 模式与 fixture 种子标识。
- 真实 iMessage / Photon 路径可收发。种子中的尺码和地址提前准备，示例信息标 `Sample`。
- 说明此次运行是 live 还是 fixture、现场还是 `Recorded run`；记录失败路径，不补造中间消息。

## 执行与取证

1. 连续录屏，从用户发出一句需求开始，保留完整对话时间线。
2. 保存原话与本次预算；显示至多两家不同商家的真实报价，统一币种单位后每条 ≤ 本次预算。记录卡上相关字段及来源，核对实际 variant 尺码；不匹配/未确认时显示说明。用户全程未重输已有尺码、地址，也没有逐次批准字段读取；缺少资料的真实追问不能剪掉。
3. 留下付款链接或已下单的真实结果。收到 `continue_url` 仅代表继续结账，不写成已经付款。
4. 若有售罄 warning 或 `requires_escalation`，录下如实回复和继续链接；不能剪成成功路径。
5. 经 SDK 的 `getActivity` / `getReceipts` 导出同时间段记录，accept 的 quoteId 对应到 agentId/sessionId；核对 accept 前没有地址放行，之后若有地址放行，仅给该商家且用途为 checkout；失败或交接时未放行也是有效结果，另一家的读取仍拒绝。发布材料隐藏敏感值。
6. 三条备选逐条独立留证，见 [Recorded run 素材清单](recording-manifest.md)。catalog-only 文件不代替手机录屏，不把旧需求视频的输入或报价改成新需求。
