# @agent-cookie/rules

Pure implementation of the published `RulesApi`: `deriveSessionId`, `mergeCard`, `renderCard`, `renderContribution`, `parseContributions`, plus the `rules` object for workspace injection. No IO, model, environment clock or policy authorization occurs here.

```sh
pnpm --filter @agent-cookie/rules test
pnpm --filter @agent-cookie/rules typecheck
```

The API uses the repository's `@agent-cookie/contract`; nested learning evidence and the preference whitelist are on main `32490f1`. B49 adds required `evidenceSources: string[]` to the local `EvidenceCard`, `LearningCardField` and `LearningCandidate` return types. This remains `TODO(contract)` until A adopts the same property on `CardField` and `Candidate`; no shared contract is changed here. Tests use Node 22, Vitest 2.1.9 and TypeScript 5.6.3. An ignored local dependency link used for validation is not a distributable dependency.

Session IDs follow the four normative contract vectors: UTF-8 HMAC-SHA256, lowercase Crockford base32, first eight characters. Inputs are not trimmed or normalized; the caller supplies the stable merchant key selected by the contract.

`mergeCard` receives one user's contributions and explicit `now` / `personalAgentIds`. For ordinary non-preference fields, including contributions carrying learning evidence, the latest live personal statement is a fixed qualification barrier: another value needs two distinct non-inferred sources after it. Without that barrier, an active older merchant consensus can be replaced by a newer merchant observation. Qualification happens before a deterministic timestamp/value ordering; input permutations cannot change the result.

Age is computed for each field/value group from its latest non-revoked, non-inferred support, not by individually deleting old source records. Exactly 180 days stays high when two sources agree; beyond 180 days becomes medium; beyond 365 days falls off the card. Expired consensus cannot promote an otherwise unqualified lone observation. Old qualified values remain in `superseded`; with no current winner, `supersededBy` is empty. Inputs are never mutated.

`changedRecently` means a single-source value replaced an already qualified live value. Initial personal statements and age decay do not set it; two-source confirmation clears it. `updatedAt` and `lastSupportedAt` use the selected group's latest support instant. These explicit interpretations are recorded for A-line alignment in `docs/requests.md`.

Contribution files retain the readable `- field: value [id: ...; basis: ...; at: ...]` format. Percent escapes preserve CR/LF, delimiters and literal percent signs; Unicode, backslashes, empty strings and whitespace round-trip. The parser obtains user and writer from the external file binding, ignores header claims and drops malformed records. CARD.md is generated with an explicit generation timestamp and includes card, candidates and superseded sections. Escaping is serialization, not model prompt sanitization; consumers must continue treating memory as data.

## Shared learning types and preview compatibility

The package imports the formal `PREF_KEYS`, `PREF_FIELDS`, `PrefField` and `ContributionEvidence` from `@agent-cookie/contract`; the existing `LEARNING_PREF_*` and `LearningEvidence` names are compatibility aliases. Field validation uses shared `isField`. `LearningContribution` additionally accepts already-written C preview records with top-level source IDs and string evidence. Conflicting top-level and nested IDs are rejected. Only the shared whitelist is accepted; a `pref.` prefix alone is not sufficient.

Both the default `rules` object and `learningRules` preserve nested evidence and whitelisted preferences. The default object remains structurally assignable to the published `RulesApi`; direct callers retain the extended return type. The wider `LearningRulesApi`, `mergeLearningCard` and `parseLearningContributions` exports remain available to C preview callers. Runtime field iteration deduplicates the shared preference list against `FIELDS`, so preferences cannot produce duplicate card entries. B49's `evidenceSources` remains a local `TODO(contract)` extension; the shared learning types are already formal.

A personal `stated` preference immediately qualifies at medium. Every other `pref.*` record requires two independent, non-revoked conversation or intent sources for the same field/value; one source remains a candidate. Two conversations from the same personal agent qualify; two agents reporting the same conversation do not. Missing provenance never falls back to writer IDs for a preference. Preference confidence is always medium. Ordinary fields retain legacy writer-based observed/stated qualification, even with evidence metadata; ordinary inferred values never qualify.

Records sharing an `intentId` or `conversationId` form one identity component, including transitive aliases. A record with both IDs links intent-only and conversation-only copies, including mixed preview/nested formats. Identity aliases use valid non-future inputs, including revoked or expired records: removing support must not split one source into two. The ID namespaces stay separate unless a record explicitly links them. `sources` lists writer agent IDs. Every card and candidate also returns `evidenceSources`: sorted, deduplicated canonical IDs in the `conversation:<id>` or `intent:<id>` namespace. A linked component chooses the lexically first conversation ID, falling back to an intent ID; revoked/expired bridges retain identity but add no live support. Equal raw strings in different namespaces remain distinct unless explicitly linked. For preferences, the returned evidence count is the count used for learned promotion (after the personal-statement barrier); a personal statement is the explicit exception and can return an empty list. Ordinary fields report their available evidence IDs but still qualify only by writer IDs. Missing evidence yields `[]`, never an invented agent ID. Callers must authenticate source IDs and authorize fields separately.

Each learned source must be at most 365 days old at explicit `now`. Future records are excluded; expired support cannot combine with fresh support. Learned consensus is medium from the start and falls off when fewer than two live sources remain. A newer qualified learned value can replace an older value; replacement of a live personal statement requires two sources strictly after that statement. Same-value preference confirmation refreshes timestamps and preserves writers at medium confidence; ordinary fields keep their existing 180/365-day decay. Ties use deterministic value ordering.

`renderContribution` preserves nested evidence in one escaped Markdown line, including an empty evidence object. Evidence snippets are limited to 200 Unicode code points, including whitespace, and oversized input is rejected rather than truncated. Default `parseContributions` now preserves all whitelisted preferences and both evidence formats, allowing A's default `openMemoryRepo` adapter to reopen and revoke them without data loss.

Generated CARD.md renders `sources` and `evidenceSources` separately for card/candidate records. The renderer still accepts an older contract-only Card input without the additive property; it does not invent evidence for such input.

Package tests cover promotion, barriers, replacement, decay, source deduplication, revocation, malformed records and Markdown round-trips. Tests and typechecks run against the current main contract in an isolated Node 22 runtime. These are package results; production model extraction and HTTP learning integration remain separate workspace responsibilities.
